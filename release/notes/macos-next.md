# Next macOS update — unreleased

## Feedback

- Help → **Report a Bug or Request a Feature…** (⌘⌥F) and Settings → General → Feedback open a sheet that files through this Mac's companion, or the first connected companion, as a public GitHub issue with your final edited title and verbatim description and up to six attachments. Included environment details are listed before sending and never contain machine names or hostnames.
- A new optional **Smart input** box above the fields accepts plain English or one inline recording. **Draft with AI** runs exactly one bounded, tool-free `issue-report-draft-v1` request on the selected companion — its validated configured Pi default model with thinking Off, at most 60 seconds — and replaces both fields atomically; the generated fields stay editable, the source text is kept, and one guarded **Restore previous** action undoes the last generation without ever overwriting a newer manual edit. The server fails closed with an actionable message when that companion's Pi default is unset or unavailable rather than switching providers, and the client enforces one deadline across preflight, start, and every poll, with bounded best-effort cleanup that never extends the busy state or accepts a late result. The mic control glows only while it actually captures and turns into Stop; a failed audio start now reports an actionable error instead of showing a fake recording, and a late callback from an abandoned capture can no longer finish the next one. Stopping sends the audio once to that companion's configured transcription service and appends the transcript to the same box, never to the title or description. There is no recorder sheet, waveform, timer, or playback UI, accessibility labels describe each state, and Reduce Motion removes the glow's fade.
- Smart-input text and recordings are sent only to the selected companion's configured Pi and transcription services and are not published. Only **File report** files the reviewed title and description word for word; a submission is never started automatically and **File report** is unavailable while a draft or transcription is in progress. Missing Pi or transcription configuration reports an actionable error without losing typed text. AI drafting requires a companion advertising `issue-report-draft-v1`; an older companion disables only that optional action with upgrade guidance, while manual reporting, attachments, recording, and transcription keep working. See docs/issue-report-smart-input.md.
- **Start the automated fix pipeline** labels the issue for the optional Code Factory daemon. Requires a companion server advertising `issue-reports-v1`; older servers show an update message.

## First Mate response feedback

- Every completed Mac First Mate response now shows compact thumbs-up and thumbs-down controls with its saved rating, including older replies, checkpoint summaries, and closed or archived features. Thumbs up saves immediately; thumbs down opens a small editor pinned to that exact response with the starting reasons **Longer than it needed to be**, **Unnecessary message**, and **Incorrect assumption**, multi-selection, a reusable custom reason added with an explicit Add action, and an optional multiline note preserved verbatim up to 4000 characters. Save can record a negative rating with no reasons, Cancel changes no rating, a failed save keeps the editor and its typed content for **Retry save**, a failed thumbs-up or **Remove rating** keeps the previous label and shows **Try again** under that response (a stale-revision conflict instead offers **Reload and retry**), the editor freezes its inputs while a save is in flight, drafts stay pinned to the revision they were loaded from until an explicit conflict reload, and changing to thumbs up or **Remove rating** clears the saved reasons and note only after the save succeeds.
- Ratings, reasons, notes, and custom categories live in the owning companion's private `first-mate.sqlite3` (not a Mac-only database) and survive companion restarts and Mac reconnects. They are never uploaded, used to train a model, or applied to conversation preferences, and recording feedback does not send a message, wake an agent, or change feature state. The editor is scoped to one feature and connection lifecycle, so switching features or reconnecting dismisses it instead of retargeting another response; saved feedback stays readable offline while writes are disabled, and a temporary outage keeps an open draft and its save error visible with **Retry connection** instead of claiming the server needs an update.
- Requires a companion advertising `first-mate-feedback-v1`; a companion that answers without it receives no feedback requests and shows one upgrade notice. A failed or unanswered capability check is treated as temporary unavailability, never as an old server. Install and restart the companion separately — the Mac updater does not install server packages. See [response feedback](docs/first-mate/response-feedback.md).

## Response briefs

- **Length** is now one app-wide choice—**Minimal**, **Medium**, or **Long**—defaulting safely to Minimal, stored independently of per-chat opt-in, model, and thinking, and applied to future requests in every chat. For multiplier `m` (1, 2, or 3), total visible content is capped at `m * max(40, min(240, floor(readable characters / 4)))` non-whitespace scalars and `m *` the existing word ceiling—at most 40/240, 80/480, and 120/720 words/scalars. A short source's allowance is a maximum, not a minimum or a padding target.
- Changing Length regenerates the brief for the source currently selected in the rail, or the latest completed answer when none is selected; re-selecting the same value does nothing, and returning to a formerly used preset still creates a deliberate fresh generation. Accepted and transport-uncertain runs reconcile under their captured preset before a replacement starts, rapid changes coalesce to the latest selection, and a pending replacement resumes once after relaunch. Selection and cancellation ordering is written atomically with a per-chat revision, so a delayed older intent write can never replace or resurrect the newest selection and a relaunch behind accepted ownership resumes only the newest authorized intent. A replacement superseded during asynchronous preflight is revalidated atomically and can never create a paid submission; **Retry** and **Reload brief support and models** resume that same queued replacement exactly once rather than starting a duplicate, and a replacement that loses a race with turning the chat off is discarded instead of resuming after it is turned back on. Other chats and saved records are not regenerated.
- A completed run with no usable brief keeps an explicit **Regenerate** control: choosing **Retry** after a settled failure preserves that actionable path instead of clearing into an empty idle rail.
- Completed answers with any non-whitespace text are now eligible, including one-character and emoji-only answers. Generated summaries have no minimum length and are never padded, repeated, or truncated; the old 160-readable-character skip and the 12–20-word guidance are removed.
- The saved-baseline warning is addressed for ordinary live-to-persisted refresh: an answer observed while live can persist under a different identifier, so the coordinator now reconciles exact identifiers, prior verified aliases, and verified identity evidence (exact content hash plus real completed-message timestamp corroborated by the user turn). Display text, ordering, labels, and screenshots never match responses on their own. The warning clears as soon as continuity is proven, and a relaunched transport-uncertain receipt stays actionable through **Retry brief** instead of hiding behind an idle rail. The rail uses the same verified equivalence as generation ownership, so a reconciled live projection keeps its **Latest** label and prior-original treatment instead of appearing as a prior source. When continuity genuinely cannot be proven, the warning stays and **Restart briefs from latest response** offers confirmed latest-only recovery that never backfills unmatched history; its latest-only intent is saved atomically with the new baseline, so recovery survives a relaunch while an earlier accepted receipt is still reconciling. The report's screenshot shows the warning but does not establish which transition its session took.
- Each new record captures the preset and policy version it was generated under, so cached records are validated against their own policy. Legacy records and receipts decode unchanged and replay byte-identical payloads; the upgrade never submits a backfill or automatically replays paid work.

## Companion compatibility

Configurable brief length is additive. The companion advertises `responseBriefs.lengthPolicyVersion` 2 with `lengthOptions`, and the Mac requires all three options before sending a new-policy request. Older clients that omit `responseBriefLength` keep the legacy prompt, budgets, and payloads byte-for-byte. A companion that only advertises `response-brief-v1` shows **Update the companion for configurable brief length…** with **Retry after updating**; the request is not sent, no generic-agent fallback is used, and existing accepted legacy runs remain reconcilable. Install and restart the updated companion separately on each machine where briefs are enabled: the Mac updater does not install or restart server packages, and **Reload brief support and models** rechecks the capability.

The configurable computer segments add optional presentation fields and a validated `localMachineId` to the authenticated machine-roster response. Existing clients ignore them. The Mac uses the self ID only for its already-saved first connection, including localhost or another origin alias; nonprimary machines still match by unique exact origin. Missing self identity preserves older-server origin fallback, while duplicate, unknown, or ambiguous claims are not guessed. The app never imports machines or credentials or rewrites saved identity. Both the companion and Mac app must be updated for self-identity synchronization, and a Mac-only update does not install companion code.

A separate companion update raises the shared headless-agent timeout, including HUD chat, from ten minutes to one hour by default. A Mac-only update does not change the running server's timeout. Existing explicit overrides remain effective; `HERDR_HARNESS_AGENT_TIMEOUT_SECONDS` supports 1–86,400 seconds through the private configuration's `[environment]` table. Cancellation remains available.

Tab color discovery is likewise additive. A companion without `chat-tab-colors-v1` keeps its existing snapshot shape, and the updated CLIs report an unsupported capability when color options are requested instead of an empty match. A Mac-only update neither installs server packages nor publishes anything until the off-by-default sharing setting is enabled. The local color store, iOS color behavior, and all existing snapshot and saved-HUD behavior are unchanged.

Local PR Review comments are Mac-only and manual-publish only. They use the review and diff data the companion already returns with `pr-review-v1`, add no endpoint or capability, and never call GitHub; the `herdr-pr-review` CLI, agent-control actions and server packages are unchanged. Records stay in a private local store shared by the main and popped-out review windows.

Main-workspace creation is additive and capability-gated. The companion advertises `quick-session-launch-options-v1` on the authenticated API; older clients keep the legacy quick-session payload, and this Mac app checks the capability before sending any new model, thinking, focus, or home-alias field. The Mac updater does not install or restart server packages, so install and restart the companion separately on each machine where checked workspace creation should run. Unchecked saved-HUD chats, history, continuation, and custom-folder behavior are unchanged.
